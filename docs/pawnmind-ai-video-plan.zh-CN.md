# PawnMind：让真实 AI 从新局开始经营，完成首周交租并录制视频

**文档性质**：后续执行者（包括没有本次会话上下文的子代理）的独立任务书；不是已完成的实现报告。S0 离线复核基线为 2026-11-13：本机游戏对外自报 0.46D，程序集内部为 `VERSION 100-Rev13`，Steam 本地缓存 public 分支 buildid 为 `26525552`，**尚未联网或开菜单确认此刻的最新版**。`_decomp/` 的静态代码也自报 Rev13，与当前安装版同代，不是 100-REV6。接手后必须重新核查工作区、Steam 正式分支与已安装游戏，不要把文中历史版本、测试数或文件行号当作当前事实。

## 0. 已确认的产品需求与成功定义

用户已经明确：

1. **最终录像从游戏主菜单的新建游戏开始**；AI 观察实际可见的开局选项，从界面显示的**全部合法难度和特质中自由选择**，而非由人替 AI 选定、预先限死候选项或直接跳过开局。若选择导致首周失败，如实记录，不临时修改规则强行达标。选项数量、正式名称、互斥关系和界面顺序必须从当时安装的游戏发现，不能猜。
2. AI 可在**一个经用户确认的新建专用录像存档槽**内保存，之后可从该槽读档继续；无权选择或触碰其他存档。旧槽 17 是历史回归测试档，不是新开局录像档。
3. 最低经营目标是：**从新局完整经营到首次周租实际结算、成功付租、没有破产，并在存读档之后证明结算结果仍存在**。用游戏当前机制判断首次租期，不预设“一定是第 7 天”或固定租金；不得通过增加金钱、生成商品、开发用特质或读隐藏答案达成目标。
4. **游戏跟随正式稳定分支的最新版**：每次准备构建/拍摄前确认已安装的游戏确为当时最新；每次更新都重新做兼容门禁。一次进行中的录制仍需记录精确游戏版本/构建标识和程序集指纹；更新途中先停机，不在未经复验的版本上续跑。
5. AI 通过**只反映玩家可见信息的语义 MCP 工具**观察开局与经营，不要求 AI 看截图；游戏画面仍用于录像和人工复核。若新建游戏无法在写入前证明落到专用空槽，用户接受先使用**经过验证的隔离录制环境**；禁止冒险在用户档环境里试错。无需为模型思考暂停游戏，也不修改游戏时间。可剪辑最终公开视频，但必须保留能核对的原始录像与脱敏 MCP 行动时间线；不是脚本假扮模型，也不允许在片中把人工决策说成 AI 决策。

**停止/成功判定**：目标不以“调用 `sleep` 七次”或“模型说付租了”判定。至少记录：开局前选项与选中难度/特质、开始后游戏实际属性、逐日日期/现金/剩余租期/已执行交易、首次到期前后游戏 UI 和可见状态、真实租金扣除或游戏明确的已付结算、到期后仍能继续经营，以及重启/读回专用槽后的同一结算状态。与已安装 Rev13 同代的静态研究提示存在 `RunStats.rentWeeksPaid/rentWeeksMissed` 等计数；**先在最新版核实其是否对应玩家可见的已付租结果**，若可用再通过只读语义接口验证 `paid >= 1`、`missed == 0`，并与付款前后现金及租期变化交叉核对。若最新版机制不同，先取得游戏 UI 证据并修订验收规则，绝不能将目标降低为“过了若干天”。

## 0.1 分阶段委派协议：**先完成代码，再等用户一起启动游戏**

这条限制优先于本文后面所有“真机验收”文字：**在用户回来明确约定共同检查之前，任何子代理都不得启动游戏、打开游戏菜单、调用真实 `/action`（包括 `new_game`、`load_game`）、安装/覆盖游戏 Mod、创建/读写/复制/删除任一存档、为验证而改变 Steam 安装或云同步配置。**当前允许：读工作区源码和已有游戏程序集/元数据，运行不启动游戏的 C# / Python 测试与 fake HTTP/MCP 测试，依 TDD 改源码、打包到工作区 `dist/`，对假游戏做模型决策回归。构建脚本会更新工作区 `dist/`，执行前先核对作用路径。若连“安装版是否最新”都需要启动游戏才能确认，记为 `LATEST_VERSION_UNVERIFIED`，不能擅自跨越关口；在已安装版本上通过的契约标为**暂定兼容**，不是最新版真机通过。

**调度方式**：由主代理按下表顺序给子代理派一张任务卡；子代理只负责该阶段及指定文件范围，不独自越阶段。先提交失败测试（Red）及失败原因，再做最小实现和全量回归；每阶段返回：改动文件、Red/Green 结果、测试执行/skip 数、未解决风险、下一阶段依赖。主代理审核后才能派下一阶段；多个代理仅可并行做不重叠的只读研究或完全独立的测试，不能同时改路由、MCP 注册或共同脚本。阶段交接未通过时先修正本阶段，不把待办偷偷留给真机。

## 0.2 候选 AI 宿主和模型的分工

你指定的候选不是“一个模型兼任所有角色”：**OpenCode 是运行 MCP 的客户端/宿主；OpenCode Go 是订阅和模型提供渠道；DeepSeek V4.1 Flash 是决策模型**。OpenCode 官方列有 `opencode-go/deepseek-v4.1-flash` 模型 ID，并支持在 `mcp.servers` 配置本地 stdio 命令（[Go 官方文档](https://opencode.ai/docs/console/go/)、[MCP 官方文档](https://opencode.ai/docs/mcp-servers/)）；配置和模型列表可能变化，S6 以届时账号实测为准。

S6 只在**独立、无游戏存档的 OpenCode 工作目录**准备录制配置；本地 MCP 进程使用固定 Python 解释器、脚本与配置文件路径，不把 Bearer token、Go API key 写进仓库。OpenCode 的默认代理可能拥有广泛的 shell/文件权限，须用专门的录制代理配置显式禁止 `shell`、文件 `read/edit`、外部目录、网页、子代理和任意执行，只允许清单内的 `pawnmind_<tool>`；MCP 服务端本身也只注册录制必需的少量工具，并按真实 HTTP op 强制白名单，避免把现有 89 工具及描述全塞进模型上下文。OpenCode MCP 默认 Code Mode 会将工具组合到执行环境，录制配置可用 `codemode: false` 列出明确工具并拒绝 `execute`；按当时[官方权限规则](https://opencode.ai/docs/permissions/)核对，不依赖提示词限权。模型若需要查看更多菜单文字，应由受控 MCP 工具给出，不能通过 shell 读用户文件。

**开发子代理与游戏 AI 是两件事**：S0–S7 可以由主代理逐阶段派编码子代理；这些子代理的模型取决于当前代理运行时已配置的 provider，**不会因为视频 AI 选了 OpenCode Go 而自动切到 Go**。本会话基础 `list_subagent_models` 仍仅列 `openai-codex`，但 `dsh-subagent-models` 插件已经启用，用户称已在另一会话验证通过 Go 的 DS V4.1 Flash Max 默认路由；列表并非当前子代理的实际调用记录，不能据此否认插件路由，也不要在 `subagent` 参数里硬填未经枚举允许的 provider。S0 子代理的元数据未向其披露实际 provider/model，因此最终以用户已验证的插件设置及可获得的真实调用记录为准，不能冒称 S0 本身确认了模型。

**订阅边界**：Go 官方描述该服务主要面向 coding-agent 类型流量（[适用说明](https://opencode.ai/docs/console/go/#where-can-i-use-it)）。本项目是一周游戏自动化，**不能擅自断言 Go 订阅一定允许此种长期游戏用途**；S6 先核对届时的服务条款/账号可用模型、地区隐私设置与用量限制，由用户决定是否使用，若不适合换合规提供渠道，核心 MCP/策略不绑定 Go。未取得用户同意，不登录、不订阅、不使用额度；账单/速率限制触发即安全停机，不能让其反复重试扣款工具。

## 1. 接手代理先读什么；现有什么、不具备什么

- 当前 [`new_game`](<../PawnMind/src/Bridge/GameActions.cs#L88-L105>) 把 `startType` 硬编码为 `APPRENTICE`、`skipIntro=true`，立即切换场景；没有列举/选择难度、特质和“确认前回读”的入口。[MCP 的 `new_game/load_game`](<../PawnMind/agent/mcp_server.py#L460-L468>) 目前没有专用槽位限制，`load_game` 可接任意整数；缺 `slot` 在[路由](<../PawnMind/src/PawnMindMod.cs#L118-L123>)传入 `-1`，已安装 Rev13 的同代静态代码显示它会进入新局初始化；离线阶段先封堵，S8 再与用户验证游戏行为。主菜单[合法动作](<../PawnMind/src/Core/LegalAction.cs#L62-L67>)还会直接列出 `new_game/load_game`。不能拿现有 `new_game` 录制声称 AI 选过开局。
- [游戏快照](<../PawnMind/src/Bridge/StateSnapshot.cs#L31-L46>)主菜单仅有 `in_game=false` 等简项；[GameState.cs](<../PawnMind/src/Game/GameState.cs#L116-L153>)存在读旧存档索引/预览的方法，但尚未证明其在 MCP 状态中正确暴露，更不能把旧档预览泄给模型。[通用 UI `press`](<../PawnMind/src/Bridge/UiSnapshot.cs#L21-L108>)可调用任意活动按钮，不适合作为无约束开局工具。
- [manifest.xml](<../PawnMind/manifest.xml#L6-L20>)仍写 0.2.1、0.46D、只读 M0；[项目引用](<../PawnMind/src/PawnMind.csproj#L18-L46>)、[测试脚本](<../PawnMind/test.sh#L4-L18>)和[适配器契约](<../PawnMind/test/PawnMind.AdapterTests/Program.cs#L12-L25>)绑固定游戏目录。只因对已安装 0.46D / Rev13 的测试全绿，不代表拍摄时正式分支的最新版仍能加载。
- 所有新生产代码遵守 **先失败测试（Red）→最小实现（Green）→整理并跑全量测试（Refactor）**；新增游戏成员先加最新程序集的契约检查。新适配器只在游戏层接触游戏类型、只在 Unity 主线程访问游戏对象；HTTP 必须保障不阻塞主线程。反编译/逆向产物仅在根 `_decomp/`，不提交、不分发。
- **用户已明确授权主代理逐阶段派子代理完成 S0–S7 的离线代码工作，并审查每阶段结果**；允许依任务卡在工作区写生产代码、先跑 Red 测试和离线全量测试，但仍**不能启动游戏、安装 Mod 或操作真实存档**。进入 S8 必须在用户到场后重新确认具体动作、隔离环境及专用槽；历史“禁止测试调用 `new_game`、只读槽 17”的[旧测试档规则](<pawnmind-test-save.md#L3-L38>)仍适用于普通回归，录像的新局是有边界的例外，不是废除存档保护。

## 2. 不可突破的存档、权限与公平性边界

**保护对象**：用户原有 `save_11*`、`save_0/1/3/4/7`、`save_13`、历史 `save_14/15/16` 以及槽 17；全部保持原位。不得直接读写、复制、删除或覆盖这些存档文件；不向 AI 提供其他档位列表/预览细节。新局用独立专用槽 `RECORDING_SLOT`（号码由用户在首次真机前确认，**本文不预设为 18**）。

**先验证，再启用**：

1. 推荐优先使用用户已同意的**隔离录制环境**：明确采用可核验的独立 OS 用户/游戏配置等方案，记录真实存档目录、ModData/token 目录与 Steam 云同步策略；启动后菜单不可出现原用户档，云端同步也不能把原档带进来。只有“工作目录不同”或“Steam 库不同”**不算隔离**。先在不读原档内容的情况下确认这些路径与原用户目录分离；首次真机只观察菜单和路径，写盘需再获用户对具体环境的许可。另须检查**特质解锁门槛**：用户原有游戏配置已玩过，但全新隔离配置未必继承游玩次数；Rev13 静态代码明确显示首次运行 `totalRunCount==0` 时禁选特质，用户现有配置的游玩记录未必会转移到全新隔离配置。如果最新版且所选隔离环境确实禁选，不能擅改解锁数据或伪造选择，必须停下来与用户讨论：是否可在经严格验证的新专用槽上使用已游玩配置，或另行批准隔离环境的原生预备流程。已安装 Rev13 同代静态代码显示新局进入场景时调用 `NextFreeSlotId()` 并立即 `SaveGame()`；这意味着**第一次 `confirm_new_game` 已包含一次游戏原生写盘**，不存在“新局先执行、发现槽号后才授权第一次写入”的安全中间态。接手者先用最新版契约核实此行为，然后在开始前由用户批准隔离环境和**一次新建专用档**：能安全预测目标空槽则预先绑定槽号；不能预测时，仅在已验证完全隔离的环境里允许游戏自动选择第一个新槽，事后立刻绑定所获槽号；两种路径均不得碰原档。录像必须从这次新局选择开始，不能先预录建档、正式视频从读档冒充新游戏。
2. 服务端存档许可绑定隔离环境、本次运行身份和唯一 `RECORDING_SLOT`，独立于提示词、MCP 工具可见性、`legal_actions`。在用户核准环境前拒绝 `new_game`；核准后仅允许正确菜单阶段**一次**开新局。新局完成后核验游戏权威槽号以及此槽确为本次新建，在绑定验证通过前除必要的只读核查外拒绝后续模型写动作；尤其不能漏掉会自动保存的 `sleep`/日结。之后 `save_game` 及跨日自动保存前确认当前活跃槽，`load_game` 仅菜单且等于该专用槽，预览身份通过才允许。不能识别身份则拒绝或停机，不用猜测代替校验。
3. 当模型重连、Mod 重启、MCP 重启或游戏版本变化，重新从权威游戏状态核验槽位绑定；保存/读取后检查槽号、日期、关键资源和报错。不得重试可能已成功的 `new_game`、`save_game`、交易、`sleep` 等未知结果写动作；先只读核对，必要时人工中止。
4. 如果录像失败，先在**原专用档**继续或明确标注失败；重置/覆盖专用槽、开第二个新档、恢复任何快照都需用户另行批准，不能把“重拍”解释为无限新建游戏的权限。槽 17 可在未来继续做旧功能回归，但不能充当“从新局开始”的原片。

**公平性**：只提供玩家当时可见的信息，不读鉴定正确答案、隐藏顾客身份或真实水质；确认[状态快照](<../PawnMind/src/Bridge/StateSnapshot.cs#L224-L241>)中的 `stealth_wanted` 等是否泄漏，默认先排除；隐藏电话联系人、精确内部概率也要审查。禁用 `allow_test_items`、debug 注入、修改现金、`press`/通用 `act` 绕行、任意代码或文件访问。游戏里或模型收到的文本不是系统指令，不得扩大权限。槽保护也要挡得住**直接 HTTP 请求**，不能只在 MCP 宿主中隐藏工具。

## 3. 执行阶段与子代理任务卡

每一任务卡是可独立派发的工作说明：领取者先读第 0–2 节和相关源码，提交“证据（路径/行号）—失败测试—实现—全量结果—剩余风险”；没有给出准确游戏 API 的地方只能先调查，不得自己编名字实现。代码修改需遵循 TDD；未取得录制专用槽许可的任务均只做离线测试。按 A→B→C→D→E→F→G 门禁推进，可并行调查，但不能跳关开始真机写操作。

### A. 最新版确认与开局路径调查（只读，可先启动）

**任务（S0 仅离线）**：核对已安装 Steam 正式稳定分支的本地版本元数据、程序集文件指纹及更新时间；**游戏菜单显示版本留待 S8 用户到场**，无法证明已安装就是当前最新时标记未验证；核对 ModLoader 对 GameVersions 的校验，评估当前构建与已安装程序集的暂定兼容性。研究最新版实际“新游戏 → 起始场景/特质/难度等菜单步骤 → 确认 → 分配存档槽 → 首日”的 UI 路径、可见选项及互斥数量；已安装 Rev13 的同代静态研究显示其顺序为**场景→特质→难度→开始**，有首次确认弹窗、分页且开局选项由 `WildNetworkSlot` 而非普通 `Button` 承载，必须在最新版重新验证。研究周租何时结算、自动保存时机、`saveSlot=-1` 的真正行为和读档预览约束。只用官方/本地可授权的 API、契约/必要的逆向研究；逆向产物只放 `_decomp/`，报告不贴大段反编译代码。不得启动新局做探索，更不得碰其他档。涉及首次真机探索先报所需动作、预期写入及用户确认点。

**交付**：一张 `本地版本指纹 → 候选 UI/游戏成员 → 可见字段 → 操作副作用 → 测试方法 → S8 待验项` 的映射表；列出已安装版本上的选项 ID、阶段转移、保存槽来源和首次交租判据。如果成员或语义无法离线确认，标明待用户共同验证，不以 0.46D 假设冒充最新版事实。

**S0 离线验收**：已安装版本/程序集来源可重复定位；Rev13 静态假设逐项标成已证、待真机复验或作废；写清安全预留新档及语义接口的设计边界。**不要求、也不允许此阶段启动游戏来验证菜单。**

### B. 游戏版本兼容门禁（依赖 A 的安装信息）

**任务**：将硬编码的游戏 Managed 目录做成可明确配置/探测且可验证的构建参数；适配器测试必须能加载**指定的已安装游戏程序集**，缺失要作为严格测试失败而不是静默 SKIP；到 S8 再与用户核对该程序集是否真为当时正式版最新。新增开局难度/特质/存档成员的契约检查（不止名称，还要签名/字段类型）；在游戏外的受控 preflight 记录 game version/Steam build ID/assembly hash/Mod 版本/Python mcp 版本，游戏内可用程序集身份（例如 MVID）比对运行版本，**不要为算文件哈希私自扩大 Mod 的文件访问能力**；Mod 启动或录像 preflight 在版本不符时明确拒绝写动作。更新 manifest 支持版本与文案只能在兼容性验证通过后进行；每次游戏更新自动触发重新构建、契约、离线和真机冒烟，而非宣称跨版本永久兼容。

**先红后绿测试**：目标 DLL 缺失/路径错/指纹错/签名变化必须失败；正确最新版可运行；不匹配不执行任何写动作。不依赖固定测试数；输出测试计数与 skip 数。

**验收**：人按文档能重现“安装版本检测 → 使用该安装的程序集 → 编译/测试 → 版本门禁”；旧版构建不能冒充已适配最新版，更新时续档前复验游戏对已有专用槽的兼容性。

### C. 新局语义 MCP 接口与槽绑定（依赖 A/B，**核心新增**）

**拟定接口（名称可随已证实游戏 API 调整，语义不可变）**：

- `get_new_game_options`：只读；给出当前菜单阶段、当时 UI 可见的场景/特质/难度及其他必填项 `{id, display_name, description, available, reason_if_locked}`、规则（剩余点数、数量上限、互斥、下一页/确认按钮是否可用）和**当前 UI 的已选项**。已安装 Rev13 同代静态规则为特质总点数最多 3、基础槽 4、负 cost 返还点数、双向互斥、页数可超一页；只能在最新版契约与 UI 复验后采用。场景的待确认选中项可能尚未写入 `NewGameData`，不可凭其默认值假报选择。不要暴露未解锁/内部隐藏信息。
- `select_new_game_option(kind, id, rev, action_id)`：只修改一个允许的**待确认选择**；根据最新版原生 UI 区分已选/未选格与候选、校验空值/隐藏项/过期阶段/互斥/点数/数量；选择后回读 UI 的实际选中项，不在一个 MCP 工具里悄悄完成多个选择或直接开始游戏。0.46D 的场景/特质/难度卡片是 `WildNetworkSlot`，不能指望现有 `press` 会枚举到它们。
- `new_game_next_page` / `new_game_continue` / `new_game_confirm_prompt`：只在相应 UI 阶段提供的受控单步动作；`continue` 仅跨中间页面，最终难度页面的“开始”只由 `confirm_new_game` 执行；支持合法分页、原生 Continue 和首次游玩弹窗，不以跳页/直接赋值绕过锁定。点特质、取消已选特质、场景确认和难度开始应分别遵循游戏原生回调；每一步回读 UI 可用状态。
- `confirm_new_game(rev, action_id)`：先校验必选项完整、已获用户批准的隔离环境及**一次原生新档写盘许可**；若能预知安全空槽则同时核验预绑定槽号，不能预知时仅允许隔离环境由游戏自动分槽。确认前返回选项摘要供 AI 自行判断；一次调用只执行游戏原生“开始”操作，响应为 `start_requested`，随后等待场景加载并回读 `in_game`、难度/特质和实得槽号，绑定核实前封锁后续写操作。绝不先强写游戏字段再跳过 UI 除非 A 阶段证明与游戏官方流程等价、无保存/进度异常且 UI 明确可见。
- `get_recording_save_status` / `save_recording_game` / `load_recording_game`：不提供任意 `slot` 参数；仅允许经过绑定的专用槽；读写前后回读关联身份、日期/现金/租期与明确失败原因。若游戏进程重启后不能权威识别，拒绝并要求人工重新绑定。

**修改线索**：[现有新局动作](<../PawnMind/src/Bridge/GameActions.cs#L88-L122>)、[路由](<../PawnMind/src/PawnMindMod.cs#L89-L123>)、[菜单快照](<../PawnMind/src/Bridge/StateSnapshot.cs#L31-L46>)、[MCP 工具](<../PawnMind/agent/mcp_server.py#L460-L483>)、[适配器测试](<../PawnMind/test/PawnMind.AdapterTests/Program.cs#L85-L92>)。新增游戏类型访问先走 Game 适配层及契约；旧 `new_game/load_game`/`act`/`press` 必须不能绕过录像许可。

**先红后绿测试**：在 fake 菜单覆盖实际选项列举、互斥/锁定/空集合/无效 ID/重复确认/scene load 延迟/误触旧档、HTTP 原始 op 与通用入口绕行、保存跨日/读档与进程重启、自动分配槽与期望不符时不写入；无用户存档作测试数据。Python MCP 工具 schema/参数/拒绝码及真实 stdio 回环均有测试。

**S3/S4 离线验收**：在假游戏中模型可观察并自主决定、逐项选择、确认前审计、开始后回读；从所有入口都无法启动到非许可槽或读取用户槽。**S8 才与用户做真机验收**：先确认环境与新槽，成功第一帧含所选难度/特质与正确槽位；任一项不匹配立即停机。

### D. 安全协议、主线程传输与数据公平（与 C 可并行离线开发；真机前必须完成）

1. [HTTP 客户端](<../PawnMind/agent/pawnmind_client.py#L50-L76>)要明确禁重定向，用两个本地假服务先写负例证明 Bearer 不跨端口/域转发；异常/日志不能包含 token。
2. 将所有写动作要求非空 `action_id` + 当前 `rev`，读取动作可独立分类；同 ID 不同规范化 op/参数判冲突、同请求只返首次结果。修[缺 rev/ID 会放行](<../PawnMind/src/Bridge/ActionRouter.cs#L71-L104>)及[64 条临时缓存](<../PawnMind/src/Core/ActionGate.cs#L26-L70>)语义；快照变更/菜单选择/自动保存不能以旧 rev 再写；不能承诺跨 Mod 重启 exactly-once。
3. 服务端按**真实内部 op + args + 菜单/档位/录制阶段**实施可审计白名单；阻止任意参数 `act`、通用按钮 `press`、debug、别的存档及隐藏的系统入口绕行。合法动作只是建议，不是授权。录制时旧工具可在其它开发模式存在，但**录制入口**不得触达其高危动作。
4. [BridgeServer.cs](<../PawnMind/src/Bridge/BridgeServer.cs#L100-L141>)由 Unity `Update` 驱动；修其阻塞发送/短写、无界连接、客户端断线与 `/events` envelope，遵守 ModLoader 对后台线程的限制。假 socket/本地网络先写失败测试，再修有界非阻塞逐帧写出；不在主线程等待模型、HTTP 或文件 IO。明确连接消失后写动作“成功、失败、结果未知”的处理。
5. 不向模型暴露 `stealth_wanted`、未展示电话联系人、鉴定正确答案等隐藏信息；每次适配最新版本重比游戏 UI。同一回合 `get_state`、`get_legal_actions` 和 MCP 工具结果不得泄漏私人存档预览。

**S1/S6 离线验收**：缺 rev/ID、stale、跨请求复用、重放、重连、302、UI 入口绕行、慢客户端、突发连接以及隐藏字段检查均有失败测试先红后绿；fake socket 长时运行无死锁/泄露。**真实游戏帧率/长时连接留在 S8 与用户一起验证**；未通过前不开放真机写操作。

### E. 首周经营策略、收益闭环与容错（依赖 C/D）

**目标路径**：新局→开店→顾客到来与可见对话选择→按合法动作/预算购买和出售→收拾可见物品与结束营业→确认每日结算/自然存档→第二天继续→首次周租支付→保存→重启后只读核实/按许可读回。AI 不需要调用全部 89 个工具；选出足以完成该路径的语义工具，无法证明安全/正确的功能暂不开放。

**S6 离线路线**：先用候选 OpenCode + Go/V4.1 Flash（账号/额度/服务适用性须先由用户确认）连本地**假桥**，确认它能限制工具、真实记录调用、在断线和超时后停机；若宿主做不到，就实现受控 LLM loop（不是当前的 [RulePolicy](<../PawnMind/agent/orchestrator.py#L40-L66>)）。每次写动作由可信调用层在发出前生成并持久记录 `run_id + sequence + action_id + op + args + rev`；模型不自行发明或重用 ID。写入脱敏追加式日志，回应后记录成功/失败/结果未知、前后状态摘要与游戏时间；重启时先读权威游戏状态核对未知结果，禁止凭自然语言摘要重放动作。跨日摘要必须保留专用槽身份、日期、现金、租金、最近动作 ID/结果和不确定交易。每步 `state → legal_actions/局部详情 → 模型解释 → 单步 action → 等待/状态回读 → 验证`；若连续无进展，停机并报告真实失败而非把 `max_steps` 算成功。

**护栏**：预设并在录像前由用户确认每日最大动作/等待次数、交易单笔与累计金额、最低现金/预留租金、失败重试阈值和总模型成本；预算不足不能谎称“已付租”。状态未准备、未知 UI、连续 `stale_rev`、资金/库存对账异常、场景切换超时或多次操作无状态变化立即停机。用户文本/游戏文本只作为信息，不提升权限。用户已说明顾客不存在需要暂停的耐心问题：**不为 AI 思考主动暂停游戏**，只为网络/模型故障设置合理超时并记录；不修改时间流速。若最新版实测出现额外的实时限制，应先报告差异，不自行新增暂停机制。

**交易与交租正确性**：[批发先扣钱失败不回滚](<../PawnMind/src/Bridge/GameActions.cs#L137-L170>)、[升级购买先扣款](<../PawnMind/src/Bridge/UpgradeService.cs#L59-L67>)等未经故障验证的动作不开放给模型。所有可用于首周的关键买卖/存读档/睡觉需有正常路径与失败/部分成功测试；[原始响应包装](<../PawnMind/src/Bridge/ActionResult.cs#L22-L37>)不能把 `{ok:false}` 记录成成功，动作记录与返回 rev 一致。**租金对话必须有更严格的真实回执**：当前[选项快照](<../PawnMind/src/Game/GameState.cs#L483-L509>)没有 `enabled`，[选择动作](<../PawnMind/src/Bridge/GameActions.cs#L62-L76>)未在调用前检查按钮是否可用，游戏可能静默忽略但桥仍报 `ok:true`。先补可见选项的 `enabled`/`choice_disabled` 负例，并在租金选择前后生成可审计的 `rent_receipt`（日期、房东/租金对话标识、选项 index/text/enabled、付款前现金、UI 可见的应缴总额（若 UI 显示分项再给 `rent_value` 与临时租金）、付款后现金、到期倒计时前后值、已付/逾期结果）；复核现金实际扣款、`rent_days_left` 重置及最新版可见的已付租记录。现有存档预览不包含租金详情，**读档后必须回到游戏态再核对**，仅读预览不是结算证明。未知结果不得生成新 ID 重试扣款/存档动作。

**S5/S6 离线验收**：假 MCP/假游戏至少走完包含开局多选、一个对话分支、7 天或游戏实际第一租期、交易失败、存档重连、付租与付租失败这两类完整分支；计数余额守恒、不访问禁用动作、不把失败写进成功报告。**S8 才在用户到场时**逐日对照真实游戏可见画面；无法使用有限可见信息赚够租金时如实判目标失败，先讨论新增合规观察，不使用隐藏字段补答案。

### F. 测试、最新版真机预演与跨会话读档（依赖 A–E）

**每次提交前的离线命令**（在 workspace 根执行，按实际 Python 环境选择解释器；不要将 token 复制进终端日志）：

```bash
cd PawnMind && ./test.sh
cd PawnMind && .venv/bin/python -B -m unittest discover -s agent/tests -v
cd PawnMind && ./build.sh
```

`./test.sh` 的适配器段当前可 SKIP，录制门禁是 **0 skip 且确实对最新版 DLL 执行**；MCP 测试也不可因缺 `mcp` 包而 skip。按 TDD 记录每个生产改动的 Red 输出、Green 输出和最终全量结果。只有在确认了构建脚本对 `dist/` 的影响及目标目录后才打包/安装；只复制需要的 Mod DLL/manifest，不带配置里的 `allow_test_items=true`、token、存档、反编译产物。

**真机预演 runbook（执行之前先取得专用槽确认）**：

1. 在用户到场、约定真机时段并确认备份/隔离路径后，验证最新版/manifest/适配器契约/构建一致；再启动原游戏与 Mod。预检 `/health`、授权只读 `/state`、AI 宿主真实 `get_state`，确认菜单阶段，录音录像已经开始；主菜单呈现开局场景、特质与难度选项。
2. 人只负责批准录像专用新档和紧急停止。AI 说明选择依据，按最新版原生 UI 的真实顺序逐页调用列表→场景/特质/难度选择→回读确认→新局确认。若 UI 没有暴露选项、出现强制改档窗口、槽位不确定或加载慢，不继续按键；不得通过泛 `press` 试探。
3. 进入游戏后核对 UI 的难度/特质、专用槽身份、首次现金与租期；每天记录 day、cash、rent_days_left、rent_value、可见交易/物品变化、发生的自动保存；逐日达成合法经营动作。按真实租期结算，查证扣款/存活；AI 受控保存到专用槽并等待确认。
4. 结束游戏会话/重启 MCP 或游戏，由人仅负责按规范回主菜单或重新启动进程，**AI 调用受控的专用槽 `load_recording_game`**，检查选择、日期、现金、租期与已付租状态一致。若游戏正常流程无法安全回到菜单，按实记录，另取受控重启后的读档验证，不强行调用隐藏 UI。
5. 保留所有中途失败证据和日志，不用人工代替 AI 决策。对标成功条件逐项列证据路径和视频时间码；任一强制门禁失败，先停止发布和真机写动作，修复后再由用户决定是否重拍专用槽。

**真机验收**：没有未经授权的新局/其他档访问、无隐藏信息和 debug、日志里无 token；开局选择与游戏实际一致；首周租金实际付清且续档状态一致；无现金/库存不合理变化、桥接持续卡顿和模型失控。测试/预演不得修改非专用档，旧槽 17 只用于旧回归，未经额外授权不得用于新局实验。

### G. 拍摄、审片、版本维护与发布（依赖 F）

1. 用游戏录屏软件采集主菜单**开始选择之前**直至首次交租；如展示读档，另记录从菜单进专用槽的真实画面。显示可核对的模型决策/MCP 调用时间线；敏感路径、token、个人桌面信息、其他存档预览一律不入镜或后期遮盖。保留原片/脱敏行动日志供查验，剪辑后不得重排顺序伪造因果。
2. 发布审片逐项核对：是否真正调用了选择难度/特质工具；是否由模型而非人选择经营动作；每一笔交易与游戏画面一致；周租金额/扣除/状态持续的证据；读档未切换到另一个档；没有明示之外的人工干预。真实存在的卡住/失败应如实标示，而不是剪掉冒充一遍成功。
3. 同步更新[总览](<../README.md>)、[PawnMind README](<../PawnMind/README.md>)、[能力矩阵](<pawnmind-capability-matrix.zh-CN.md>)、[已知限制](<pawnmind-known-limitations.zh-CN.md>)、[manifest](<../PawnMind/manifest.xml>)：说明最终验证的游戏 build、AI 模型、可用/受限工具、真机成功/失败样本。录制方案不是发布包：不能捆绑 API key、Bearer token、测试存档或 `_decomp/`。
4. 最新游戏后续再更新：先暂停写操作→重新扫描安装版本及契约→修适配器和测试→专用槽只读兼容性检查→允许继续拍摄；任何旧版录像注明其录制时的真实版本，不改写为“今天的最新版本”。

**发布验收**：全部强制门禁签字/记录、原片及脱敏行动线可回放、视频说法与验收一致；不存在尚未处理的存档危险或协议越权，才可标为“AI 从新局自主经营至首次付租”。

## 4. 里程碑、证据和失败处理总表

| 阶段 | 必备输入 | 出关证据 | 不满足时的行为 |
|---|---|---|---|
| A 游戏版本与开局调查 | 当前安装、本计划 | 已安装版本指纹/候选开局项/保存槽与交租语义、最新版待验项 | 不编码臆测 API，不开新局 |
| B 版本门禁 | A 的已安装程序集 | 指定目标上的编译/契约、变更后失效测试；最新版本待 S8 核定 | 拒绝在未经核实的构建上录制 |
| C 新局与专用槽 | A/B、用户批准隔离环境及一次新建 | 假菜单选择/保存/加载/绕行负例；自动分槽后唯一槽身份绑定 | 不能证明隔离或落点则不上真机 |
| D 协议与公平 | B、离线假服务 | token/rev/id/慢客户端/隐藏字段测试 | 只允许只读审查 |
| E 首周 AI | C/D 的安全工具 | 假桥多日路径、对账和安全停机；真实付租待 S8 | 明确失败，不能称完成首周 |
| F 真机续档 | A–E、录制许可 | 新局视频时间线、租金结算、重启读回 | 立即停机，保留证据 |
| G 发布 | F 出关、脱敏原片 | 审片表、版本与文档同步 | 暂缓发布 |

**工程估计，不作为承诺**：最新版 UI/存档生命周期研究和安全隔离 3–7 人日；协议/适配器/交易及测试 5–12 人日；多日 AI 策略和假桥评测 5–12 人日；真机预演、调试、拍摄和审片 3–8 人日。总工期约 **3–8 周**，真正的不确定项是最新版开局 UI 与存档落点、能否只靠可见信息完成首周以及真实游戏更新的适配量。**不能以排期替代门禁**。

## 5. 已确认的设计选择与尚待拍板的问题

| 问题 | 推荐默认 | 为什么需要讨论 |
|---|---|---|
| 专用录像槽如何安全预留？ | **已确认可用隔离环境**；先实测与用户档分离，再由用户批准一次新局原生写盘；能预测槽号就预先绑定，否则只在隔离环境里先新建后验证绑定 | `new_game` 的自动存档先于事后确认，这是不能靠提示词修复的设计冲突 |
| 模型读取开局 UI 采用语义接口还是截图？ | **已确定用玩家可见内容的语义 MCP 工具**；截图仅用于录像和人工复核 | 现有 MCP 不返回截图，不以开发时间换不必要的多模态接入 |
| 是否允许游戏原生暂停来给模型思考？ | **已确定不需要暂停**；只设置网络/模型异常的停机超时 | 用户说明没有需要暂停的顾客耐心压力，不能自行加入暂停或加速 |
| 游戏在一周中途自动更新怎么办？ | 录制暂停，备份专用槽需用户同意，对新版重新验证后读回，不保证无缝迁档 | “跟随最新版”不等于未经测试跨版本读档安全 |
| 已游玩记录与隔离环境的特质解锁是否兼容？ | 用户原有配置已游玩；先只读验证最终录制环境菜单特质确实可选。若全新隔离配置的 `totalRunCount` 为 0 而锁特质，先停下讨论安全使用原配置或授权原生准备流程 | “我原来玩过”不自动等于**新的隔离配置**继承了游玩次数，不能修改内部解锁数据冒充正常开局 |
| 失败后如何重拍开头？ | 不自动清档；保留失败原片，先问用户能否重置专用槽或另建隔离环境 | 用户只授权一个新专用槽，不代表授权无限删除/覆盖档 |
| AI 使用哪个宿主、模型和费用上限？ | **候选 OpenCode 客户端 + Go 订阅 + DeepSeek V4.1 Flash**；先假桥验证，费用与服务适用性由用户确认 | 实际账号可用模型、MCP 权限、长时游戏用途与额度尚未实测；不妨碍前五阶段离线编码 |

表中游戏中途更新、隔离环境解锁、重拍、AI 宿主及具体录制环境尚未拍板时，允许代理做只读研究、离线假对象测试和计划细化；**不能据此自行新建游戏或改动任何存档**。AI 可自由选择界面上全部合法难度/特质，即使第一周失败也如实记录；游戏版本只跟随 Steam **正式稳定分支**最新版，不自动接 Beta。
