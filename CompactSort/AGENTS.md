# AGENTS.md — Compact Inventory Sort

Instructions for AI coding agents working on this mod.

## 0. 铁律：所有功能开发必须 TDD

任何**生产代码**变更（`src/`、`manifest.xml` 中的行为描述、安装/构建脚本逻辑）都必须按 Red → Green → Refactor 进行：

1. **Red**：先写一个测试，明确期望的用户可见行为；运行 `./test.sh`，确认它因为缺少该行为而失败。把失败输出留在记录里，不要先改生产代码。
2. **Green**：只写让该测试通过的最小实现，不顺手重构无关逻辑。
3. **Refactor**：在测试全绿的前提下整理代码；每一步都重新运行测试。
4. **Full suite**：提交/打包前必须运行完整 `./test.sh`，不能只跑单个用例。

禁止：

- 先改生产代码，再补一个“跟着实现走”的测试；
- 为了让测试通过而放宽断言、删断言、跳过用例；
- 只测 happy path，不测失败/回滚/边界；
- 用“游戏本身的问题”解释 bug 而不留下可重复的回归测试；
- 把未经测试的适配器改动直接打进 `dist/`。

例外仅限纯文档、注释、格式化、日志文案；即便如此也不能改变行为。

## 1. 测试命令

```bash
cd CompactSort
./test.sh                 # 全量测试
./test.sh BBoxGap         # 只跑名字匹配的用例
```

测试项目：`test/CompactSort.Tests/`。它不依赖游戏进程、不联网，直接编译 `src/Packing/` 的纯算法源码。`build.sh` 会先运行 `./test.sh`，测试失败时不会生成安装包。

## 2. Bug 修复规则

每个线上 bug 必须先有一个**回归测试**，命名 `Regression_<short_name>`，并尽量复现用户看到的失败模式：

- 物品丢失/重复 → 断言每个 `PackPiece.Id` 恰好出现一次、父容器/位置合法、失败时回滚；
- 同格重叠（包括不同 layer）→ 断言 `StrictOccupancy` 下任意两个物品不共享格子；
- 碎缝变多 → 断言新布局在 `IsolatedHoles`、`EmptyComponents`、`BBoxGap` 的字典序上不差于旧布局；
- 锁定物品被移动 → 断言锚定格子的占用和 owner 不变；
- 全局池/暗格/展示柜 → 先测“收集边界”和“提交前校验”的纯逻辑；如果当前只能靠反射或游戏对象验证，必须先抽出可测的纯函数或测试缝，不能只写“手动试一下”。

如果 bug 只在 Unity 运行时出现，至少要做到：

1. 把决策逻辑抽成不依赖 `UnityEngine` 的纯函数并单测；
2. 在 `test/IN_GAME_CHECKLIST.md` 增加对应的手动验收步骤；
3. 在最终回复里明确说明“自动测试覆盖到哪一层、哪一层仍需进游戏验证”，不能声称已自动覆盖。

## 3. 测试分层

### A. 纯算法单测（每次必跑）

覆盖 `src/Packing/`：

- 放置合法性：边界、墙、锚定物品、严格占用、旋转、空输入；
- 守恒：每件物品恰好放一次，不复制、不丢失；
- 目标函数：死洞、空格连通块、包围盒空隙、最大空矩形、同物品/同类别接触；
- 算法一致性：Greedy / Beam / Hybrid / SA / GA / B&B 都不能产生非法布局；
- 随机性质测试：固定 seed，生成多组矩形，断言不变量；失败时打印 seed 和用例。

### B. 适配器契约测试（改动 `CompactSorter` 时必须补）

优先把“选容器、分组、校验、提交/回滚”拆成可注入的纯逻辑；用 fake inventory 测：

- 提交前所有目标位置都通过校验；
- 任一件失败 → 整体回滚，原父容器/形状恢复；
- 目标容器原物品只 reshape，不批量 Expel/Accept；
- 锁定/展示柜/垃圾桶/前台-后台-内部柜台不被收集；暗格应被收集；
- 全局池提交后每件物品仍在某个合法容器中。

当前测试项目只编译 `src/Packing/`，不引用 `Assembly-CSharp`。需要新增适配器测试时，新增独立 csproj，不要让纯算法测试依赖游戏 DLL。

### C. 游戏内验收（不能替代单测）

`test/IN_GAME_CHECKLIST.md` 是发布前的人工验收清单。任何触及拖拽、全局池、容器收集、撤销的改动都必须走一遍，并保留 `Player.log` 关键行。

当前已有一版只读自动自检：

- 游戏内按 `F8`，日志输出 `[CompactSort][TEST] PASS/FAIL ...` 和 `SUMMARY pass=N fail=N`；
- `test/ingame/check_selftest.py` 解析日志并以 0/1/2 退出；
- `test/ingame/press_f8.ps1` 负责激活窗口/发送 F8（不负责加载存档）。

它只覆盖真实场景的容器绑定、排除列表、重叠/越界，不覆盖真实提交/撤销/拖拽。新增这类逻辑时，优先把决策抽成纯函数/测试缝；无法抽出的，必须在 `IN_GAME_CHECKLIST.md` 增加步骤，并在最终回复说明未自动覆盖。

## 4. 断言质量标准

- 测**行为**，不测私有实现细节；允许为了可测性抽公共纯函数。
- 固定随机 seed；不要依赖真实时间、帧率、UI 布局或游戏进程。
- 时间预算类测试用宽松上界，不断言精确毫秒。
- 质量类断言优先用**相对比较**（新布局不差于旧布局），少用容易随启发式波动的精确分数。
- 失败信息必须包含：seed、容器尺寸、物品列表、期望/实际指标。

## 5. 构建与安装

```bash
./test.sh          # must be green
./build.sh         # runs test.sh first, then csc build + dist/
```

安装目录：`...\Probably Stolen\Mods\CompactInventorySort\`。游戏运行时 DLL 被锁定，先退出游戏再覆盖；不要在游戏运行时假装安装成功。

## 6. 安全不变量（所有排序路径）

- 不销毁、不复制、不修改 `unitCount`/品质/耐久；
- 任意两个物品不共享同一格（无论 layer 是否相同）；
- 锁定物品、残骸、固定家具不动；
- 展示柜、垃圾桶、前台/后台/内部柜台不参与自动整理；`hiddenElement` 应参与；
- 自动整理失败时保持原布局，不留下半提交状态；
- 全局池必须先全量校验再提交；提交失败必须回滚。
